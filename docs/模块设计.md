  - 详细职责：实现 token 解析、用户缓存（短期）、群组到角色映射策略、处理登录回调与会话续期逻辑；提供测试替身（fixture）以便单元测试绕过真实飞书。

- `app.bitable`：BYTableClient 封装，主类 `BYTableClient(api_token)` 提供方法：
  - `get(table_id, record_id)`
  - `query(table_id, filter, page, size)`
  - `create(table_id, data)`
  - `update(table_id, record_id, data)`
  - `batch(table_id, ops)`
  - 详细职责：
    - 支持两种模式：`real`（调用 Bitable HTTP API）与 `mock`（内存实现）。
    - 对外保证幂等操作的接口（如 create 带 client-side id），并为批量操作做重试与速率控制。
    - 提供分页迭代器与字段映射工具，方便将 Bitable 字段映射到内部 Pydantic 模型。

- `app.models`：Pydantic 模型定义：`User`, `Material`, `Inventory`, `Transaction`, `Category`, `Location`。
  - 详细职责：定义输入/输出验证规则、字段注释与示例（用于自动生成 OpenAPI 文档），并提供序列化/反序列化工具。

- `app.middleware.auth`：角色鉴权中间件/依赖（`require_roles(*roles)`），在路由或前置中间件中使用。
  - 详细职责：在请求上下文中注入 `current_user`，并在鉴权失败时返回统一 403 响应；支持路由级别或全局配置。

- `app.api.materials`：材料相关路由，包含 `search`, `get_by_id`。
  - 接口与行为：
    - `GET /materials/search?q=&category=&location=&page=&size=`：支持关键词、分类、库位过滤，返回分页结果与总数。
    - `GET /materials/{id}`：返回 `Material` 及其 `inventory` 聚合数据。
  - 输入校验：q 字段长度限制，page/size 上限限制（防止大页查询）。
  - 错误码：1001=参数错误，4004=物料未找到。

- `app.api.inventory`：库存查询接口，返回按库位汇总的数量。
  - 接口与行为：
    - `GET /inventory?material_id=&location_id=`：支持多种条件组合，返回列表或聚合视图。
    - 支持缓存（短期 30s）以降低 Bitable 查询压力。

- `app.api.transactions`：入库/出库创建接口，包含幂等 key 校验与事务写入逻辑。
  - 接口与行为：
    - `POST /outbound`、`POST /inbound`：请求体包含 `material_id, location_id, qty, idempotency_key, note`。  
    - 后端流程：鉴权 → 校验库存（出库）→ 写 transactions（PENDING）→ 更新 inventory → 设置 transactions（COMPLETED）。
    - 幂等策略：在 Redis 或内存缓存中短期保存 idempotency_key 的处理结果（有效期 24 小时）。
  - 并发与一致性：建议使用行级锁或乐观重试（compare-and-swap）来避免并发更新导致库存负值。

## 辅助模块与工具

- `app.admin`：管理 API，例如 `POST /admin/bulk-sync`、`GET /admin/health`。仅 ADMIN 可调用，支持分页、dry-run 模式。

- `app.tasks`：后台任务模块（可选），实现异步同步、数据修复脚本与报表生成。

- `app.utils`：通用工具集，例如请求 ID 生成、时间工具、重试装饰器、字段映射工具。

```json
{
  "material_id": "mat_001",
  "location_id": "loc_01",
  "qty": 5,
  "idempotency_key": "uuid-1234",
  "note": "出库给门店A"
}
```

成功响应示例：

```json
{ "code": 0, "message": "ok", "data": { "transaction_id": "tx_20260611_0001" } }
```

失败示例（库存不足）：

```json
{ "code": 4002, "message": "库存不足: 当前可用 3", "data": null }
```

## 前端模块

- `src/api/index.ts`：统一封装 HTTP 客户端与接口方法：`getMe()`, `searchMaterials(q)`, `getMaterial(id)`, `postOutbound`, `postInbound`。

- `src/pages/Search`：搜索页，输入框、结果列表、分页、跳转详情。

- `src/pages/Detail`：展示物料详情、库存、流水历史，并显示出入库入口（基于用户角色）。

- `src/pages/Inbound`：入库页面（仅 KEEPER/ADMIN），包含物料选择、库位、数量、备注、提交。

- `src/pages/Outbound`：出库页面（KEEPER/ADMIN），相似入库但方向相反。

- `src/components/AuthGate`：基于 `getMe()` 的权限控制组件，控制按钮显隐。

## Bitable 客户端设计要点

- 网络与重试：对 Bitable 请求做重试与错误分类（4xx、5xx）。
- 批量操作：提供 `batch` 接口以减少 HTTP 调用次数。
- 映射：在 BYTable 与内部模型间做字段映射与类型转换。

## 测试策略

- 后端：用 `pytest` 对 `BYTableClient`（可 mock requests）、关键业务逻辑（入/出库幂等、权限校验）做单元测试。
- 前端：对 `src/api` 用简单的集成测试（mock fetch），对关键交互（搜索→详情→出库）做端到端 smoke 测试（可选）。
