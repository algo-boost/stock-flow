## 快速命令（复制即用）

```bash
# 系统安装（示例：Windows winget）
winget install --id Git.Git -e
winget install --id Python.Python.3 -e
winget install --id OpenJS.NodeJS.LTS -e

# 后端
cd backend
python -m venv .venv
.\\.venv\\Scripts\\activate   # Windows
pip install -r requirements.txt  # 或 pip install fastapi uvicorn lark-oapi python-dotenv
uvicorn app.main:app --reload --port 8000

# 前端
cd frontend
npm install
npm run dev
```

BITABLE_TABLE_MATERIALS=tblxxxxxxxx

## 6. 风险管理与应急预案

### 6.1 主要风险识别

| 风险 | 影响 | 应对 |
|------|------|------|
| 飞书 API 接口变更 | 后端集成延期 | 提前验证 lark-samples 版本，预留 1 天缓冲 |
| Bitable 权限配置复杂 | 权限不生效 | 6月11日下午提前验证，出问题立即反馈飞书 |
| 前端样式适配问题 | 移动端显示异常 | 6月16日重点关注响应式，必要时削减功能范围 |
| 缺陷数量超期望 | 测试时间不足 | 6月17日起按优先级严格分类，P0/P1 必修，P2 可后置 |
| 网络延迟 / 隧道不稳定 | 联调困难 | 多准备 2 个隧道方案，必要时用内网服务器 |

### 6.2 应急预案

#### 如果 6 月 14 日晚全量联调失败？

**降级方案**：
1. 确保「搜索 → 详情 → 出库」三个 P0 功能可用
2. 入库功能（P1）推迟到 6 月 16 日再集成
3. 测试周期改为 1.5 天

#### 如果 6 月 17 日还有 P0 级 bug？

**决策点**：
- 若 bug 修复 < 2h：继续修复，6 月 18 日再验证
- 若 bug 修复 > 2h：上线后通过热修复处理，产品方决定是否延期

#### 如果 6 月 19 日上线后用户反馈严重问题？

**应急流程**：
1. 快速定位（产品 + 技术）
2. 30 分钟内判断是否需要回滚
3. 若回滚，准备已测试的前一个稳定版
4. 若继续，立即修复 + 热部署
