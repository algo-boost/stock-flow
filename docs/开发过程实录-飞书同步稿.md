## 一、案例背景：我们要解决什么问题？

机器人研发实验室需要管理分散在货柜、货架、专用架上的硬件物料（电机、传感器、算力板、线缆等）。现状痛点：

- 找物料靠个人记忆，效率低
- 领用、入库缺少标准记录，难以追溯
- 快递到货后暂存与正式上架流程不清晰
- 库存数量靠人工记账，易出错

**团队特征**：小团队、专人维护、低访问量（每天几十笔操作以内），已在飞书协作。

**产品目标（一句话）**：记清楚、找得到、可追溯 —— 不是做 ERP，不是高并发 WMS。

## 四、最终技术架构（截至 2026-06-10）

```text
飞书工作台
    └── 网页应用（React H5）     ← 用户操作界面
            └── FastAPI            ← 免登、鉴权、业务、Bitable API
                    └── 飞书多维表格  ← 唯一数据库（五表）
```

**五表模型**：categories、locations、materials、inventory、transactions

**MVP API（8 个）**：

- `GET /auth/feishu/callback`、`GET /auth/jsapi-config`
- `GET /me`、`GET /materials/search`、`GET /materials/{id}`、`GET /materials/{id}/transactions`
- `POST /inbound`（KEEPER+）、`POST /outbound`（ALL）

## 六、可分享的方法论（案例价值）

### 6.1 我们做对了什么

1. **从已有 Wiki 出发，而非白纸** —— 快速建立共识
2. **每轮对话都落文档** —— PRD/架构版本化，避免口头决策流失
3. **先问「有没有现成的」再写代码** —— 调研 Erniu、应用模式、lark-samples
4. **约束驱动简化** —— 「低访问量、专人维护」砍掉 80% 过度设计
5. **规则固化** —— Cursor Rules 让 AI 后续不跑偏
6. **组合创新而非从零创新** —— 模板 + 脚手架 + 薄自研
