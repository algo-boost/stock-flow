# 飞书应用全栈开发方法论

> 基于「物料出入库管理系统」两周实战提炼  
> 技术栈：飞书自建应用 + Bitable 多维表格 + FastAPI + React (antd-mobile)

---

## 一、核心原则

### 1.1 反造轮子，拿来就用

```
开源模板（Erniu/lark-samples） + 飞书原生能力（Bitable/审批/群组） + 自研薄层
```

| 拿来用 | 自研 |
|--------|------|
| 飞书免登 JSAPI | 角色校验中间件 |
| Bitable CRUD 基础封装 | 业务 API（8 个 MVP） |
| 官方 UI 模板参考 | H5 页面（4 页） |

### 1.2 开发顺序：mock → real → 部署

```
第 1 天：mock 模式 + 本地跑通全流程
第 2 天：切 real 模式 + 飞书联调
第 3 天：部署 + 飞书工作台嵌入
```

Mock 模式切换：`.env` 里 `BITABLE_MODE=mock`，请求带 `X-Mock-Role: ADMIN`，秒级可测。

## 二、架构三板斧

### 2.1 三层缓存，不裸调飞书 API

```
请求 → ① 内存 dict（TTL 300s）→ miss → ② SQLite WAL（持久化，永不过期）→ miss → ③ 飞书 API（1.5~7s）
```

**关键教训**：SQLite 作为持久化兜底，**绝不能和内存缓存共用 TTL**。内存过期后直接读 SQLite，后台异步刷新。否则 5 分钟后缓存形同虚设，每次回源飞书。

### 2.2 httpx 连接池复用

整个进程共享一个 `httpx.AsyncClient`，每次 new 多花 200~500ms TCP+TLS 握手。

### 2.3 写操作用 idempotency key

所有写 API 必须带 `idempotency_key`（UUID），后端做幂等校验。飞书 API 超时重试不会重复写。

## 三、前端开发规范

### 3.1 组件删 UI 必须同步清理

删除一段 JSX 后，务必同步删：
- antd-mobile 组件 import（Button/Dialog/Form/Input 等）
- 对应的 useState / useRef / useMemo
- 事件处理函数
- API 函数 import

**漏一个就会 TS6133 报错**。删完跑 `npx tsc --noEmit` 验证。

### 3.2 危险操作三步确认

| 步骤 | 机制 |
|------|------|
| 1. 预检查 | 按钮 `disabled={stock > 0}` / 角色判断 |
| 2. 菜单 | ActionSheet 危险项标记 `danger: true` |
| 3. 确认 | `Dialog.confirm` 二次确认 + 不可恢复警告 |

### 3.3 ActionSheet + Dialog 时序陷阱

```tsx
// ❌ 错误：先清状态再调 handler，handler 里 if (!target) return 直接拦截
onAction={async (action) => {
  closeMenu();                    // target = null
  await handleMenuAction(action); // 检查 target → null → return
}}

// ✅ 正确：让 handler 内部自己关
onAction={async (action) => {
  await handleMenuAction(action);
}}
```

### 3.4 Layout 嵌套问题

独立页面（`/purchase`）自带 `<Layout>`，但嵌入 tab 时（`<StockPage>` 的进货 tab），会双重包装导致两个导航栏叠加。解决方案：把内容组件单独 export（`PurchaseContent`），独立路由用 `PurchasePage`（含 Layout），tab 内用 `PurchaseContent`（不含 Layout）。

### 3.5 缓存数组用 useMemo

Layout 的 tabs、showBack 等每次渲染重建会导致子组件不必要的重渲染。用 `useMemo` 包裹。

## 四、后端开发规范

### 4.1 Bitable 字段用专用解析函数

```python
field_link_id(v)    # link 字段
field_user_name(v)  # 用户字段
field_number(v)     # 数字字段
```
**绝不**用 `fields.get("字段名")` 直接取值。

### 4.2 鉴权模板

```python
# 中间件：从 Bearer token / X-Mock-Role 解析用户
# 角色：通过飞书 IM 群组成员判断 ADMIN/KEEPER/USER
# 兜底：环境变量 FEISHU_ROLE_OVERRIDES 强制指定（IM 权限未开通时）
```

### 4.3 冷启动预热

`lifespan` 里从 SQLite 回填内存缓存，避免首次请求回源飞书 API（省 1.5~2.5s）。预热失败不阻塞启动。

### 4.4 路由前缀统一

所有 API 路由用 `APIRouter()` + `app.include_router(prefix="/api")`，不要像 `feishu_events` 那样把 `/api/` 硬编码在装饰器里。

## 六、常见错误速查

| 错误 | 原因 | 修复 |
|------|------|------|
| SQLite 有数据但还拉 Bitable | 共用内存 TTL 判过期 | SQLite 独立 TTL 或不过期 |
| ActionSheet 点了没反应 | `closeMenu()` 提前清空 target | 让 handler 内部清 |
| 页面出现两个导航栏 | 嵌套 `<Layout>` | 导出无 Layout 的内容组件 |
| `git pull` 冲突 `.db` / `tsbuildinfo` | 生成文件在仓库里 | 加入 .gitignore 并 `git rm --cached` |
| TS6133 大量报错 | 删 JSX 没清理关联代码 | `npx tsc --noEmit` 逐行修 |
| 审批"通过"直接执行 | 缺确认弹窗 | 加 `Dialog.confirm` |
| 历史页修改/删除无效 | closeMenu 时序问题 | 见 3.3 |
| PM2 本地找不到 | PM2 在服务器上 | 本地用 `npm run dev` + `uvicorn` |
